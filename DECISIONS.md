# Decisions

Format: date — decision — why — alternatives rejected.

## 2026-07-22 — Committed by brief (not revisitable without human sign-off)

- pnpm workspaces; `packages/{protocol,vite-plugin,extension,panel}` + `apps/playground`.
- Panel in iframe served by bridge at `http://127.0.0.1:7331/panel`; panel owns the WS.
- Bridge in-process via `configureServer`; Vite's watcher does the HMR half (no manual reload).
- v1 className support: static string literals only, conflict-group aware. `clsx`/`cva`/expressions → `editable: false`.
- Tagging transform is parser-based (`@babel/parser` + `magic-string`), not a Babel preset, so it works under both plugin-react and plugin-react-swc.

## 2026-07-22 — M0 choices

- **Playground on Tailwind v4 + React 19** — the newer/harder target; a v3 fixture project gets added in M2 for the adapter, per brief.
- **Workspace packages export raw `.ts` (`exports: "./src/index.ts"`), no build step.** All three consumers (Vite plugin in Vite's Node process, panel via Vite, extension via its bundler) can consume TS source in dev. Publishing builds can come when we publish.
- **pnpm installed via `npm i -g`** — corepack shim install needs admin on this machine (EPERM in Program Files).
- **Playwright M1 gate drives the protocol directly** (WS client in the test) rather than loading the MV3 extension in CI, per brief's explicit allowance; extension QA'd manually.

## 2026-07-23 — Feature-sweep choices (user requested all roadmap features)

- **Drift radar scans DOM class attributes**, not source — DOM mirrors source for class strings, and it keeps the radar zero-bridge-traffic. Upgrade path: resolve-backed scan when CSS-in-JS support lands.
- **Contrast math converts any CSS color via the browser** (hidden probe element + getComputedStyle), so v4's oklch palette works without a color library.
- **Prop-chain attribution v0 is a name-match scan** (call sites of the enclosing component that pass className), not import-graph tracing. Full attribution is its own milestone per brief §OP3.
- **Variant blast-radius v0 is an informational list** of cva variant combos in the file, not rendered previews — rendering isolated variant grids needs a component-mount harness we don't have yet.
- **MCP server is dependency-free stdio JSON-RPC** proxying the bridge WS — same constrained pipeline, ~150 lines, no SDK.
- **Instance-vs-component v0**: clicking always edits the definition (the stamp lives on the definition's root host element) and the panel says so explicitly every time; call-site links offer the per-instance edit; non-forwarding components say so. Automatic call-site *editing* (adding a className prop) is deferred to full M4.
- **Deferred: CSS Modules / styled-components / vanilla CSS write-back (OP10).** Routing by styling system + CSSOM winning-rule resolution is a separate subsystem; half-shipping file writes into CSS would violate "refuse loudly, never guess". Tailwind-path refusal already covers these elements safely (`computed-classname`).
- **Deferred: branch/PR mode and the LLM mode** (M6) — `/export` markdown changelog is the seed for both.
- **Still owed for the full M2 gate**: a real Tailwind v3 fixture project (v3 path is implemented via `resolveConfig` + unit-tested logic, but not proven against a real v3 app).

## 2026-07-23 (later) — cva editing, typography groups, agent transports

- **cva editing (M5) ships for the same-file case**: `className={button()}` resolves to the cva base + the *active* variant slots (defaultVariants merged with literal call args); edits target the slot that owns the group, new groups land in the base. Dynamic variant args, non-literal bases, and cross-file cva imports refuse. Cross-file resolution is the known ceiling.
- **Typography/appearance conflict groups added to the engine** (text-size, font-weight, font-family, tracking, leading, rounded*, shadow, opacity) — required so panel font controls can't blind-append `text-lg` beside `text-sm`. `font-<custom>`, `shadow-<color>`, and `text-[arbitrary]` deliberately parse as "not ours" and are left untouched.
- **`POST /api` agent transport**: the WS message handler is shared with a plain HTTP endpoint so Codex/Cursor/CI can drive the pipeline with curl; same origin policy as WS. `AGENTS.md` is the agent-facing contract.
- **Panel defaults to light theme** with a persisted sun/moon toggle (user preference); token lists for typography/appearance are the standard Tailwind sets, hardcoded in the panel (they're spec, not project config — spacing/colors remain config-driven).

## 2026-07-23 (later) — Opus multi-agent audit: 23 confirmed bugs fixed

Ran a 6-dimension Opus finder + adversarial-verify workflow (30 agents). 23 confirmed bugs fixed, 1 refuted (a timing race that same-thread task ordering prevents). All have regression coverage (57 engine unit + 3 e2e).

Engine (source-corruption class — highest priority): text-align/wrap/overflow no longer misclassified as text-color (`TEXT_NON_COLOR`); bg-blend/opacity/clip added to `BG_NON_COLOR`; cross-segment clsx duplicates now stripped from all args (`removeTokenGroup`); segment content spliced from raw source not babel's cooked `.value` (HTML entities/escapes preserved); unified-diff hunk header now counts context lines (valid `git apply`).

Bridge/MCP: WS handler wrapped in try/catch (malformed frame no longer crashes the process) + empty-bulk guard; bulk undo resolves composite keys and undo always replies (`unknown-edit` reason added to protocol — no more silent client hang); `/health` no longer leaks the absolute root; `/api` body capped at 1 MB; MCP requests serialized + id-matched (no cross-talk on concurrent tool calls).

Extension: per-inspect nonce on the fiber round-trip (page scripts can't forge `wb-fiber`).

Panel: serialized edit queue fixes paste-only-first-token and rapid-click stale-hash refusals; multi-select re-resolves all elements after a bulk; `matchGroup` bg/text/shadow sets synced with the engine; copy guards against refused elements; `MANAGED` trimmed to groups that actually have editors (no phantom "editable" chips); `resolved` guarded by loc.

**UX shipped from the review:** hover label badge (tag + dimensions), bridge connection dot + auto-reconnect + disabled controls when down, Escape to deselect (then exit), approve bar scrolls into view, success toast on commit, keyboard-operable collapsible sections (role/tabindex/aria-expanded), aria-labels on icon controls, journal-undo reachable on focus.

**UX deferred (low value / larger):** roving-tabindex in the swatch grid, an explicit apply button on the custom-color input, "mixed" value display when multi-selected elements disagree, a drift-radar toggle button in the panel header. (All four subsequently shipped in the staging/UX pass below.)

## 2026-07-23 (later) — Renamed to "Writeback"; staging model; agent-experience tuning

- **Product renamed VCE → Writeback** across packages (`@writeback/*`), the plugin export (`writeback()`), the DOM stamp (`data-wb`), the journal dir (`.writeback/`), the MCP bin (`writeback-mcp`), health (`{writeback:true}`), env (`WRITEBACK_PORT`), and all docs. Logo: a "return-caret" mark (assets/logo-*.svg), embedded in the panel header + extension icons (rasterized to PNG); brand sheet kept editable in `artifacts/brand.html`.
- **Panel switched to a stage → Save/Reset model** (user requirement: don't write on every click). Controls preview live via inline styles; Save writes the whole draft through the serialized queue; Reset discards. Custom bracketed values flag `raw`.
- **Agent-experience pass, driven by an Opus A/B test (traditional vs Writeback on an identical task).** First run: Writeback LOST (10 calls / ~4200 tokens vs 3 / ~1450) — the agent wasted a config fetch (~3.5k tokens) and hit a misleading `computed-classname` on a wrong path. Fixes:
  - `file-not-found` refusal reason (was misreported as `computed-classname`), and the resolve reply carries `root` so path errors self-correct without a `config` call.
  - **Column-tolerant resolve**: pass just a line (`col:0`); if one JSX element is on it, snap to it and echo the element's real `loc`. Agents grep→line→resolve→edit without reading the whole file.
  - **Post-edit `hash` in every `edited` reply** + documented **`bulk` with multiple ops on one loc** → multi-property edits in one call, no re-resolve.
  - **Server-side off-scale enforcement** (`reason:"off-scale"`) so the "agents can't emit off-scale values" guarantee is real over /api+MCP, not UI-only. Bracketed values need `raw:true`. This lets agents skip `config` for known tokens (off-scale is the safety net).
  - AGENTS.md now leads with the fast path. Re-test: Writeback WINS — 0 full-file reads (vs 1), ~1050 task tokens (vs ~1450), risk none (vs low); and the gap widens with file size since traditional cost scales with the file while Writeback's stays flat (grep+resolve). Locked into e2e.

## 2026-07-25 — Full M4: per-instance call-site editing

- **`target:'callsite'` on the edit message** (one optional field, plus the same field per `bulk` entry) is the whole protocol surface. Rejected alternatives: a new message type (`instanceEdit`) — duplicates the hash/dry/journal plumbing for one flag; and a new `Loc` kind — locs are positions, not intents, and every other consumer would have to learn it.
- **The forwards check is enforced server-side, not trusted from `resolved.instance.forwards`.** A client that skips resolve, or resolves a different element, would otherwise write a class the component silently drops. Refusal reason `not-forwarded` — the sixth reason, added because reusing `computed-classname` would tell the agent to go edit the file by hand when the real answer is "style the definition instead".
- **The forwarding check is AST, not a regex** (it was the v0 regex over the declaration's source text; three adversarial reviews all landed on the same false positives — an unrelated `{ className: 'x' }` object key, a `{...props}` spread onto a nested child). It now requires a real link: a `className` param binding (destructured, defaulted, or `props.className`) or a whole-props object that reaches a **root-level** JSX element's `className` attribute or spread. Anything less refuses. Followed across relative imports + barrel re-exports (same hop budget and confinement as cross-file cva, via the same `EditHost`); unresolvable definition = `not-forwarded`, i.e. refuse rather than assume. Known limit: a component that spreads props onto a root element it renders *conditionally* still counts as forwarding.
- **The append is sanctioned only because it creates a NEW attribute.** "Never blind-append" is about tokens inside an existing class list, where stylesheet order decides the winner; `<Card>` → `<Card className="px-4">` adds no competitor to any list. It is still an AST-placed splice with reparse-verify, and it is the only place Writeback writes an attribute.
- **Cross-BOUNDARY conflicts warn, they do not refuse.** A call-site class can still collide with one the component sets on its own root (`clsx('px-2', className)` with no tailwind-merge → both reach the DOM, stylesheet order picks the winner). We cannot fix that from the call site — removing the component's class would restyle every other instance — so the write proceeds with a `warn` naming the colliding token. Refusing instead would kill per-instance editing for nearly every real component; silence would be the "blind append" the hard rule forbids. `twMerge`/`twJoin` in the component suppresses the warning.
- **The `not-forwarded` gate applies to the default target too, not only `target:'callsite'`.** Omitting `target` on a component-usage loc reaches the same attribute, so it was a way around the gate.
- **A computed className at the call site refuses** rather than reaching into it — an instance edit that resolved a `cva()` there would land in the definition file, which is exactly what the caller asked to avoid.
- **Panel UI deferred** (a redesign is in flight): the capability ships on the protocol, `/api`, and MCP, and is covered by a live e2e (`<Badge>` in the playground forwards className, `<Card>` deliberately does not).

## 2026-07-25 — Adversarial-review fixes (Features 1-3)

- **`export *` is resolved LAST in both chain-walkers.** ESM: a module's own export shadows a star re-export. `findExportedCva` checked stars first, so a barrel that re-exported *and* defined the same name edited the shadowed file — the rendered one untouched, an unrelated component silently mutated. `exportedComponentInfo` already had the right order; they now agree.
- **Local `cva` lookup is scope-aware.** It took the last matching declarator in the file, so a private `const chip = cva(...)` inside one component answered for another component's `chip` — and received the write. Resolution now takes the innermost declarator whose scope contains the element; exported-binding lookups only consider module scope.
- **The optimistic lock covers every file the edit depends on.** A cross-file cva edit is decided by two files: the call site picks the element and the variant slot, the definition receives the write. Hashing only the definition let a call-site change silently retarget the write. `hash` is now `sha256(hash(callsite) + ':' + hash(definition))` for cross-file edits (unchanged plain file hash otherwise) — opaque to clients, which echo it rather than computing it, and `resolved.editFile` names the write target so nobody has to guess. Same rule in `bulk`, where hashes are checked against each file's PRE-BATCH content: the old "skip the check if the target is already staged" let one valid edit launder the stale hashes of every edit behind it.
- **The `edited` reply echoes the ELEMENT's loc, never the cva definition site.** A `cva(` call is not a JSX element, so the advertised "chain edits without a re-resolve" refused `computed-classname` on the second call — and reported it as "this element is unsupported".
- **`locked-group` is its own refusal reason, and `resolved.locked` advertises it.** Feature 1 refused conditional-branch groups as `computed-classname`, contradicting the same element's `resolved` reply and (in `bulk`) aborting the whole batch with a reason meaning "not editable at all". The lock also now covers tokens whose group is AMBIGUOUS (`text-[20px]` → text + text-size), which `parseToken` declines to classify and which therefore locked nothing.
- **`node_modules` refusal is case-insensitive** — the guard is a hard rule and the filesystems we run on are not case-sensitive.
- **The bridge has tests** (`test/bridge.test.ts`): hashing, staging and journalling over the real HTTP transport against a real on-disk project. Every defect above was in glue that 125 pure-function tests could not see.

## 2026-07-25 (later) — Feature A: variant-aware editing (hover:/focus:/dark:/md:/lg:)

- **No engine change was needed, and that is the point.** `parseToken`/`applyTokenEdit`/`removeTokenGroup` have keyed conflict groups by **(group, variant-chain)** since M1; the panel was the only thing hard-coding `variants: []`, and its `matchGroup` returned null for any token containing `':'`. The work was making the client speak the protocol it already had. Server-side gates (`offScale`, hashing, bulk staging, undo) are value/group-level and needed no variant awareness — now pinned by tests rather than assumed.
- **One chain active at a time, chosen from a fixed chip row** (`base · hover: · focus: · dark: · md: · lg:`), not a free-text chain builder. Arbitrary chains (`md:hover:`, `group-hover:`, `data-[state=open]:`) are writable over `/api` and MCP today — the engine takes any chain — but a UI that offers infinite combinations turns a design-system tool into a class-string editor. The chip row is the 90% set; the wire stays fully general.
- **Draft keys became chain-qualified (`bg` vs `hover:bg`).** Base and variant edits of the same property stage independently and both land in one Write, because they are genuinely different conflict groups. Splitting on the LAST `':'` is safe: no group name and no variant name contains one. `#text` has no chain — text content is not stateful.
- **The base chain is byte-for-byte today's behaviour.** `matchGroup(cls, group, want = '')` defaults to the empty chain, which is exactly the old `if (cls.includes(':')) return null`. Every existing call site keeps its meaning; only the token-strip highlight changed (a `hover:` token now reads as managed, because it now *is*).
- **No live preview off the base chain — and we say so.** A `hover:`/`dark:`/`md:` class cannot be faithfully faked with an inline style: the state and media belong to the page, and a preview that lies is worse than no preview. Non-base chains show a hint line ("no live preview for this state; Review shows the exact diff") and rely on the dry-run diff, which is exact. `draftStyle()` filters to base-chain keys, so a staged `hover:` edit never leaks into the preview of the base state either.
- **Computed-style fallback is suppressed off the base chain.** The picker's computed values describe the element at rest; showing them under `hover:` would present the resting colour as "the current hover colour". Off base, a group with no class reads `—`.
- **A read-only conditional branch still locks its group across every chain.** `on && 'hover:bg-blue-500'` locks `bg` for base *and* `hover:` edits: `lockedGroups` deliberately ignores variants. Conservative on purpose — the branch and the edit end up in the same className declaration, and we cannot know which wins. Narrowing the lock to the exact chain is possible later; refusing costs a legal edit, allowing one would corrupt a render.
- **Copy/paste carries variant tokens, each back into its own chain** (not into the active one) — otherwise "copy styles" would silently flatten `hover:` into base.

## 2026-07-25 (later still) — Feature B: per-instance editing in the panel

- **`resolved.own` is a new server-side field, and it had to be.** `resolve` answers "what does this element render": for `<Badge className={button()} />` that is a cva definition's class list in a third file. A per-instance edit writes the USAGE's own `className` attribute and nothing else, so driving the panel's controls from `classes` would have shown classes the edit can never touch — and offered edits `applyCallSiteEdit` refuses. Deriving it in the panel was not an option (never regex source in a client), so `ownClassesAt` reads it from the same AST path the write takes: `parseJsx` → `findElement` → `staticAttrRange`. The two cannot drift, because a shape the write refuses is exactly the shape that reports `classes: null`.
- **`own: { classes: [] }` means editable-empty, not "no classes to edit".** A usage with no `className` at all is the append case M4 already sanctions — the write creates the attribute. Reporting it as a refusal (the way top-level `reason: 'no-classname'` does for the element) would hide the single most useful instance edit: styling a bare `<Badge>`. The panel shows the full control set and says *"no classes yet — edits will add them"*.
- **`own` is present only for a PascalCase component usage.** Host elements are edited through the ordinary path and can never enter instance mode, so the field's presence doubles as the client's "is this call-site-editable at all" test — no second round trip, no client-side guess about JSX shapes.
- **Instance mode is a mode, not a second selection.** The panel replaces `sel` with the call site and stamps `instanceOf` on it; everything downstream (staging, chip row, rail, dry-run, Write, copy/paste) is unchanged code addressing a different loc, and `editTarget()` adds `target:'callsite'` to every `edit` frame. The alternative — a parallel set of instance-aware controls — would have doubled the surface for one field's difference.
- **The entry point lives on the refusal card too, not only the definition banner.** The realistic per-instance case (`cn(base, className)` on the component's root) *refuses*, and `render()` returns before the banner. Offering "Edit only this instance" only in the banner would have shipped the affordance to the one case that doesn't need it.
- **Live preview stays ON in instance mode.** Unlike the variant chains, the preview here is not a guess: the DOM element the picker selected IS the instance being edited, and the class lands on that element because the component forwards it.
- **Text editing is suppressed in instance mode.** `applyTextEdit` has no `target`, and the usage's children are not the same node as the rendered element's text. Leaving the component to edit its text is the honest route; offering a text box that wrote somewhere else is not.
- **Multi-select leaves instance mode rather than widening it.** An instance draft is a statement about one usage; bulk-applying it to a shift-clicked sibling would silently write call sites the user never opened.
- **Fixed while in here:** `render()` declared `const chain = sel.components…`, shadowing the module-level variant chain — so Feature A's "editing hover:" hint line rendered on every selection with the component crumb list in it. The local is now `crumbs`.
- **The panel now has an e2e test that drives the panel.** It loads `/panel` top-level (the bridge serves it, and it talks to its parent window, which is itself) and postMessages a `wb-select` exactly like the extension does. Every previous e2e drove the wire protocol directly, which could not have caught a client-side regression in any of this.

## 2026-07-25 (later still, again) — Feature C: `@theme` design-token editing (closes M5)

- **A new message (`{t:'token'}`), not a new `EditOp`.** Every other client message names a `Loc` and edits JSX; this one names a *token* and edits CSS. Folding it into `edit` would have meant a loc that points at nothing, a `target` that isn't an element, a hash that locks a different file, and an `offScale` check against the very scale being redefined. The reply shapes are unchanged (`edited`/`refused`), so journal, undo, `/export` and the panel's History work with no branch anywhere.
- **Hand-written CSS scanning, and the reason it does not violate "never regex against source".** The hard rule exists because a regex cannot see structure. This scanner can: it tracks comments, strings, parens and brace depth, finds top-level `@theme` blocks (`@theme`, `@theme inline`, `@theme static`), and only then locates the declaration. Adding a CSS AST dependency for one value splice failed the no-new-dependency bar. The safety comes from the same place as the JSX path: splice → **re-scan the result** → the file must still declare the same tokens, in the same order, and ours must read back byte-for-byte the value asked for, or nothing is written.
- **Everything ambiguous refuses.** Declared twice (in one file or two), declared inside a nested block, a comment inside the value, or a value containing `; { } /* */ \ newline` — all refuse rather than pick a winner. `config.tokens` lists *exactly* the set the server would accept a write for, so the panel can never render an affordance for a token that will refuse.
- **Only existing tokens are editable.** Creating one is a design decision (which file, which block, what scale does it join, what does it break) that a click cannot make. An unknown name is `unknown-edit` — deliberately the same reason as an unknown undo id: "there is nothing here by that name".
- **Reasons are reused, not invented.** `unknown-edit` (no such token), `parse-error` (ambiguous CSS, or a value that would escape the declaration), `hash-mismatch` (the CSS file moved under us). A seventh `RefuseReason` would have bought nothing a client acts on differently.
- **`hash` is optional and locks the declaring CSS file.** `config.tokens[name].hash` is the token to echo, and the index is re-scanned on every `config` request so a manual CSS edit invalidates it. Optional because agents legitimately edit tokens without a prior read; the panel always sends it.
- **The bridge's `scale` stopped being a constant.** A token write moves the design system, so `getScale` is re-run after a token edit *and* after an undo that touched a `.css` file — otherwise the off-scale gate would keep enforcing the old palette and `config` would keep serving it.
- **No dry-run for a token edit.** The whole change is one value in one declaration, and the confirm step already states it in full; a server round trip to preview a one-line diff is ceremony. (`edited` still carries the unified diff.)
- **The panel confirms, and refuses to pretend it can count the blast radius.** A token edit is the only edit here that does not go through the write rail — staging it beside class edits would imply it is the same kind of change and would let it ride along in a Write the user was thinking about differently. It is its own two-step action in amber (the "bigger than this file" colour): value → *"Changes every use of this token — the panel can't count them"* → Apply. Counting honestly would need a full utility scan of every source file; guessing low would be worse than saying nothing.
- **The affordance is on the swatch, not just the current value.** A ✎ badge is pinned to any colour swatch the server called editable (plus a ring, plus "· project token" in its title), so a token's *definition* can be reached without first applying it to the selected element — clicking the swatch still just uses the colour. The same ✎ appears on the colour block header and beside the font `select` (a `<select>` cannot hold a button) when the current value is a token.
- **Known limits:** only `--color-*` and `--font-*` tokens have a panel affordance (spacing tokens are edited through the scale's steppers and have no swatch to hang a pencil on); `@theme` blocks are found under `src/` at depth 3, the same scan `getScale` uses, so a stylesheet outside `src/` is invisible; and MCP has no `edit_token` tool yet — agents reach it over `POST /api`.

## 2026-07-25 (end of day) — Feature D: checkpoint mode (M6 seed)

- **A checkpoint is a snapshot, never a state change — and that is enforced by which git commands exist in the code, not by care.** `doCheckpoint` uses `git branch` (creates a ref, cannot move HEAD) and the plumbing set `read-tree` / `update-index` / `write-tree` / `commit-tree` / `update-ref`. There is no `checkout`, `reset`, `stash`, `switch` or even `git add` anywhere in the bridge. Nothing in that list can write the working tree, so "your branch and files are untouched" is a property of the vocabulary rather than a promise.
- **A throwaway `GIT_INDEX_FILE`.** Staging through the real `.git/index` would clobber whatever the user had staged. Every checkpoint command runs against an index file in a `mkdtemp` directory, removed in a `finally`. That is also why only journal-touched files can end up in the commit: the index starts as `read-tree HEAD` and receives exactly those paths.
- **Only the session's own files, at their current on-disk content.** A manual edit sitting in the tree is the user's business; adopting it into a Writeback commit would be a silent claim of authorship. Journal-touched files that have since been deleted are skipped rather than failing the batch.
- **An empty journal refuses `unknown-edit` rather than making an empty commit.** Same reading as an unknown undo id: there is nothing here to act on. No new `RefuseReason` for it. `git-unavailable` *is* new, because "no git / no repo / no HEAD" is a fact about the environment a client should report differently from a rejected edit — and it is only ever sent with nothing left behind (a half-made ref is `branch -D`'d before refusing).
- **`writeback/<yyyymmdd-HHmmss>`, with a `-2` suffix on collision.** Two checkpoints inside one second must not clobber a ref, so the name is probed against `refs/heads/` first. Local time, not UTC: the branch name is for a human scanning `git branch` on their own machine.
- **The commit body is always the session changelog** (`exportMarkdown()`), passed via `commit-tree -F -`. It contains diffs, i.e. anything a source file can contain, and must never be shell-quoted onto a command line. The subject is the user's message or `writeback: N edits`. **No co-author trailer** — per the brief, and because the commit is the user's edit history, not the tool's.
- **No dry-run and no rail.** A checkpoint writes no file and changes nothing reversible-looking; previewing it would be previewing a ref creation. The reply names the branch, and `git log` is the review tool.
- **The panel asks for the subject INLINE, and this is a correctness requirement, not taste.** The first cut used `prompt()`. The panel really ships as a cross-origin iframe (`127.0.0.1:7331` inside the app's origin), where Chrome *ignores* `prompt()` and returns `undefined` — the dialog would simply never appear for the only client that matters, and the `undefined.trim()` that followed would have thrown. The composer is now real DOM in the footer, beside the History whose entries it commits, following the Feature C inline-editor precedent. It is teal rather than Feature C's amber: a token edit rewrites the design system, a checkpoint changes nothing the user can see.
- **Armed by the journal.** The button is disabled while the session has no writes, and an open composer closes if an undo empties the journal underneath it — an open form aimed at nothing is worse than no form.
- **`.ckedit[hidden] { display: none }` is load-bearing**, not defensive CSS: the UA rule for `[hidden]` loses to any class that sets `display`, so the composer rendered permanently open until this was added. Caught only because the e2e asserts visibility rather than the attribute.
- **The e2e deliberately never sends the frame.** The playground root lives inside this repository, so a real checkpoint from a test would branch and commit the developer's own working copy. The browser test covers the half only a browser can see (inline composer, focus, toggle, Escape, ✕) and asserts no `writeback/*` ref appeared; the git half is covered in `bridge.test.ts` against a `mkdtemp` repository with hermetic identity and signing disabled, where the load-bearing assertions are that the checked-out branch, HEAD, the index and `git status --porcelain` are byte-identical across the checkpoint.
- **Known limits:** no MCP tool (`checkpoint` is reachable over `POST /api`); no way to list or delete the branches the tool made; the journal is not cleared by a checkpoint, so two checkpoints in a session produce two overlapping commits rather than an incremental one; and a checkpoint of a session whose files were later hand-edited commits the *current* content, not the content Writeback wrote.

## 2026-07-25 (review pass) — hardening after three adversarial reviews of A/B/C/D

- **Class tokens are validated on their CHARACTERS before any splice, and that is a new hard rule.** Reparse-verify proves the *file* parses; it cannot prove the edit stayed inside the string literal. `p-4" onClick={eval(…)} z="` and a variant of `${require('fs')…}` both produce perfectly valid JavaScript — the first grows an event handler on the user's element, the second turns a static template literal into live code that Vite then HMRs into the running app. `validTokenEdit` (src/classlist.ts) is applied to the whole emitted token, variant prefixes included, on `applyEdit`, `applyCallSiteEdit` *and* in the bridge's `offScale` gate: no whitespace, no `" ' \` { } $ \`, chain segments may not themselves contain `:`. `raw: true` is an escape hatch from the design *scale*, never from this.
- **The refusal reason for an invalid token is `off-scale`.** It is the same statement the scale check makes — "that is not a value this tool will write" — and inventing an eighth `RefuseReason` would give clients nothing to act on differently.
- **The WS/`/api` origin allowlist is now the bridge's OWN origin, and nothing else.** `http(s)://localhost:<any port>` admitted every other dev server, Storybook, docs site and coverage report the developer had open — a drive-by page could `token`, `checkpoint`, `undo` or `open` with a `text/plain` POST (a CORS *simple* request: no preflight, and the attacker never needs to read the reply). `chrome-extension://*` was worse: a scheme, not an allowlist, admitting every installed extension. The panel is served BY the bridge, so it already runs on `http://127.0.0.1:7331`; Writeback's own extension never opens the socket (it pings `/health`, which is read-only and CORS-open, and iframes the panel). Callers with no `Origin` header at all — agents, curl, CI, MCP — are the local user and stay allowed. One-line setup is untouched: no secret to copy, nothing to configure.
- **`{t:'token'}`'s `hash` became REQUIRED (a wire-type change).** It was the one write that changes every element in the project and the only one that would accept "no lock at all". It is now gated on the client having just read the file it rewrites — defence in depth behind the origin allowlist, since an unauthenticated caller cannot guess the hash either. The panel always sent it; agents fetch `config` first anyway to learn the token names.
- **Confinement is checked on the REAL path.** `resolve()` normalises `..` but a symlink planted in the project still points wherever it likes, and `writeFileSync` follows it. `safePath` now compares `realpathSync` against the real root, and `cssFiles` no longer follows links or yields non-files, so a linked-in stylesheet is never even offered as an editable token.
- **A variant chain is a SET, not a string.** `hover:md:p-2` and `md:hover:p-2` compile to the same rule, so they are one conflict group; comparing the chains byte-for-byte made them two and blind-appended a competitor, with stylesheet order left to pick the winner — precisely what the never-blind-append rule exists to stop. `chainKey` (sorted, de-duplicated) is the identity used by `applyTokenEdit`, `removeTokenGroup`, `applyEdit`'s segment choice and `callSiteGate`. Not reachable from the panel (its chip row is single-segment) but fully reachable over `/api` and MCP, which is where multi-segment chains are documented.
- **Whitespace between class tokens is preserved.** A multi-line `className` is a formatting choice; rebuilding the list space-separated collapsed it, claimed changes in the diff/journal (and now in a checkpoint commit) that the user never made, and fought their formatter. Surviving tokens keep their own separators, a removed token hands its trailing whitespace to the token before it, and an append reuses the separator between the last two tokens — so a multi-line list stays multi-line.
- **Locked groups are inert in the panel, not merely annotated.** They rendered live controls whose every write the server was certain to refuse; that was also the reachable trigger for the dry-run bug below. The controls are shown (the value is still worth reading) but disabled, staging refuses with a toast, and paste skips them. The banner now says *read-only in every variant* — the server drops the chain when it locks a group, so `hover:bg` is just as locked as `bg`.
- **The dry-run is tracked by message id, not by a counter.** A refused op zeroed the counter while its siblings' replies were still in flight; they decremented it negative, which (a) rendered a DRY-RUN box containing only the ops that passed while Write would apply the whole draft, and (b) left `dryPending` at `-1` forever, silently disabling Review. Now the panel holds the set of ids it is waiting on: an unknown id is ignored, and a refusal inside a review abandons the whole review rather than previewing a partial truth.
- **Every selection change resets the whole per-selection state.** The two call-site jump links reset only `draft`, leaving `multi` (the next Write silently became a bulk onto an element the user could no longer see), a stale variant chain, and a token editor belonging to the element just left. `jumpTo()` is now the single path, matching `wb-select` / `enterInstance` / `exitInstance`.
- **A resolve reply for an element that is no longer selected still decrements the pending count.** Selecting something else during a multi-element write left `busy`/`saving` true forever — every button dead until the socket reconnected.
- **`afterResolve()` runs before `render()`.** The write clears the draft in `finishSave`, so rendering first painted every just-written change as still pending (strikethrough `from → to` wells, `.staged` rows, `+ token` chips) while the rail had already vanished.
- **Undo of a token edit re-fetches `config`.** The file came back but the panel kept the undone colour, the undone prefill, and — worse — the undone lock hash, which refused every later token write as `hash-mismatch` until reconnect. Any `edited` reply naming a `.css` file now refreshes the design system.
- **A refused token write puts the editor back with the typed value.** The commonest refusal is a stale lock, whose recovery is "send the same value again after config refreshes" — discarding the input made that impossible to do without retyping.
- **The token ✎ toggles per (token, control).** The same token has a pen in both colour blocks; keying the toggle on the name alone made the second pen close the editor instead of moving it under itself.
- **`loc.line` for a token edit points at the declaration, not the value** (they differ when the value wrapped onto the next line) — it is what jump-to-source uses.
- **Dismissed:** `AGENTS.md` not documenting `token`/`checkpoint`/`own` is real but is a docs-pass item, not a defect fix. The reviewers' remaining checkpoint coverage gaps (rollback after a failed commit, unborn HEAD, detached HEAD) are untested claims rather than reproduced defects and are left for a later pass.
- **Known limits:** the two symlink-confinement tests skip on an unprivileged Windows box (creating a symlink needs Developer Mode), so that pair only runs on CI/macOS/Linux; and the origin allowlist assumes the panel is reached at the bridge's own origin — a user who reverse-proxies the panel onto another port would be rejected.
